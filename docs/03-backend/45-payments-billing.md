# Payments and Billing

Two different things: **customer payments** inside each company's books, and **platform billing** (what the owner charges companies). Behaviour of the first is in [18-business-logic.md](../05-logic/18-business-logic.md); this file adds screens, accounts and the second.

## Customer payments
| Topic | Rule |
| --- | --- |
| Modes | Cash, UPI, card, bank transfer, cheque, wallet, store credit; each can have its own account |
| Counter | One tap per mode; UPI QR waits for confirmation; manual "Received" needs a reason and is flagged in the shift report; cash drawer opens through the receipt printer (manager-only Open drawer action) |
| Split / part | Pay disabled until lines equal the total or the balance is marked Credit; invoice shows Paid, Balance, Due date, chip Part paid |
| Advance | Receipt without an invoice sits on the customer, offered on their next invoice |
| Cheques | Received → Deposited → Cleared \| Bounced; a bounce reopens the invoice |
| Bank reconciliation | Statement lines left, book entries right, suggested matches confirmed by the person; unmatched lines become a journal |
| Refunds | Linked to a credit note or return; original mode where possible |
| Reminders | Send reminder on overdue invoices; optional automatic WhatsApp/SMS from a template |
| Cards | No card numbers stored; gateway token only |

## Platform billing (Console: Plans and billing)
What a company pays for decides what it can use: plan and add-ons set the entitlements, the super admin can override any module or feature, and an item that is off is hidden everywhere (see [22-authentication-authorization.md](../06-security/22-authentication-authorization.md)).
| Part | Rule |
| --- | --- |
| Plans | Default modules and limits; moving to a smaller plan lists what switches off and what stays readable; nothing deleted |
| Subscriptions | States Trial, Active, Past due, Grace, Suspended; extend trial, apply credit |
| Limits | Users, branches, invoices per month, storage; notice to the admin at 80%; at 100% the Add button explains the limit |
| Failed payment | Banner during grace → read-only → blocked ("This page is not available" wording + Contact us); the Counter keeps billing offline for a set time so a shop is never stuck at the till |
| Invoices to companies | Generated by `platform-billing`; usage meters feed them; Usage screen shows meters and plan invoices, **never** company records |
| Add-ons | Billing only, e-billing, HR as separate add-ons via the agreement |
| Offboarding | Data export status, deletion date, final invoice |

## Open
Pricing values, trial length, grace period length, offline-billing allowance while suspended: owner to supply.

## UPI at the counter in release 1 (D-055)
The Pay screen shows the **company's own UPI QR** (its VPA and name) and waits for the cashier to confirm; "Received" without a gateway confirmation needs a reason and is flagged in the shift report. This avoids a gateway and its fee, and keeps working offline. A payment gateway (dynamic QR with confirmation callbacks, payment links, subscriptions) is a later add-on behind the same `PaymentPort`. UPI merchant-fee rules were reported inconsistently in October 2026 (a network fee of 0.4% on UPI above ₹2,000 reported from 15 October 2026 by some sources, still a proposal per another); treat gateway cost as unknown until confirmed.
